## Part 1 — Assessment of Gemini's `future_improvements.md`

Three of its five findings reference technologies this project does not use. Verified against the code:

| Gemini claim | Reality (verified in phase7d) |
|---|---|
| "SQLite with rusqlite; set WAL mode and busy_timeout" | The app uses **DuckDB 1.10505 bundled** (`src-tauri/Cargo.toml:25`, `src-tauri/src/db.rs:7`). DuckDB is single-writer with its own concurrency model; rusqlite pragmas do not apply. The underlying concern (long rebuilds starving UI queries) is real in principle but the roadmap reports a full rebuild of ~2 s on the owner's record, so it is a non-issue today. If contention ever appears, the correct fix is a dedicated pipeline connection — not SQLite pragmas. |
| "Adopt React Query with `staleTime` / `gcTime`" | The app uses a **custom `useAsync` hook** (`src/lib/hooks.ts`) with `data:changed` invalidation, not React Query. Swapping the data layer for react-query is a large dependency change for marginal gain. The underlying point — memoizing chart derivations — is valid (see Part 2, item 3). |
| "Shell scripts lack `set -euo pipefail`" | `setup-linux.sh:5` and `build-linux.sh:3` already have it. |
| "Standardize loading skeletons" | **Valid.** No skeleton components exist anywhere in `src/pages/` or `src/components/` (grep for `animate-pulse`/`Skeleton` returns nothing). |
| "Memoize chart components" | **Valid.** No `useMemo`/`React.memo` anywhere in `src/components/charts/`. Since `useAsync` re-runs on every `data:changed` event (e.g., a 20-minute poll tick), calendar/heatmap data derivations repeat on every poll. |

**Verdict:** keep Gemini's doc as a checklist, but annotate it with the corrections above so nobody applies a rusqlite migration to a DuckDB codebase. The two genuinely useful items from it are chart memoization and loading skeletons; the rest should be re-derived (below) against the actual stack.

## Part 2 — Technical Recommendations (Kimi)

Ordered by priority.

### T1 (P0) — CI test job + build gating
`build.yml` never runs `test_sql_fixtures.py`, `validate_sql.py`, or the three `scripts/smoke-*.ts` scripts — yet the smoke scripts already run against `dev-server.mjs` with **no Rust compile needed**. Meanwhile every push to `main` triggers a full Linux+Windows build (~40 minutes, against the 2,000 free minutes/month on a private repo).

- Add a ~2-minute `test` job (ubuntu, `pip install duckdb pytz`, `npm ci`, run fixtures + smokes) and gate pushes on it.
- Reserve full Rust builds for `v*` tags and `workflow_dispatch` only.

**Cost saved immediately; regression coverage gained for free.**

### T2 (P1) — Structured error envelope at the Rust boundary
`commands.rs` uses `CmdResult<T> = Result<T, String>` throughout. Low urgency today, but the deferred LLM phase (Ask, theme playlists) must distinguish "token expired" / "Ollama unreachable" / "quota exceeded" / "DB busy" in the UI. Add a `{code, message}` envelope now and grow it; retrofitting later touches all ~565 lines of `commands.rs`.

### T3 (P1) — Chart memoization + loading skeletons
The valid remainder of Gemini's items, done in-place: `useMemo` for matrix/grid derivations in `CalendarHeatmap`/`WeekHourHeatmap`, and a shared `CardSkeleton` used by `Dashboard`/`Insights`/`Explore` while `useAsync` is in its loading state. No new dependencies.

### T4 (P1) — Global "attended only" lens
The "So Excited" saga (229 plays, 226 of them unattended) fixed *detection* (`stuck_repeat`, interaction allow-list), but the time still counts in every total, streak, and record. Add a settings toggle that excludes unattended-flagged sessions from dashboard aggregates, and make `is_interaction` a first-class filter in `sessionQueries.ts`. The hard part is built; this is the payoff.

### T5 (P1) — Rust connector parse tests
The roadmap itself states the Rust layer has had "exactly one real compile-and-run cycle." The highest-bug-density Rust code is response parsing in `connectors/{lastfm,musicbrainz,listenbrainz,statsfm,coverart}.rs`. Record one real response per endpoint as a JSON fixture and unit-test the parsers. No network, no OAuth — catches the "upstream renamed a field" class of bug that the borrow checker cannot.

### T6 (P2) — Quota transparency on the Services screen
API-07 compliance (backoff, `Retry-After`, midnight quota pause) is buried in Rust. Surface per-service counters: calls used today, pause state, per-connector last-sync result. Turns "why hasn't my art loaded" from a support question into a visible state.

### T7 (P2) — One restore drill
Nightly Parquet backups of `events` are kept 14 days (NFR-03). Verify a restore actually works once via a documented command. Backups that have never been restored are hopes, not backups.

### Explicitly rejected from Gemini's doc
- **rusqlite WAL pragmas** — wrong engine (see Part 1).
- **React Query migration** — wrong abstraction; the custom hook + memoization achieves the goal.
- **Prepared-statement caching** — DuckDB's planner handles this at this scale; premature pooling adds risk to the least-proven layer.

## Part 3 — New Roadmap Features (Kimi)

Ordered by value-to-effort. Items already listed in the roadmap's §3 (art plumbing, playlist grouping, earworms move, session cards, heatmap scope, outlier hygiene panel) are confirmed as correct priorities and not repeated.

### R1 — Artist co-listening network (the missing signature visual)
`session_transitions` and per-session artist co-occurrence are already computed in SQL. A D3 force graph — "artists that share your sessions," nodes sized by plays, colored by scene — is the one visual the original spec promised ("D3 for the force graph and rivers") that does not exist yet. The taste-drift map (Phase 4) already proves the layout math works on this codebase.

### R2 — Command palette (Ctrl+K)
The app has ~20 pages. A fuzzy palette over pages + artists + tracks is cheap (the search SQL already exists) and pays off daily.

### R3 — Attention-adjusted streaks & records
Once T4 exists, recompute streaks/records both ways (all plays vs. attended only) and surface whichever is more interesting. A looping-speaker night should not extend a listening streak.

### R4 — Concerts via Setlist.fm
The `concerts` table and `concertsFor()` query already exist; only the connector and entry UI are missing. Free API key; feeds the "songs played around shows you attended" bump on artist pages.

### R5 — Deezer energy/BPM connector
Keep as a Phase 8 candidate, but **verify the public API still serves the needed fields before committing** — its public surface has been shrinking.

### R6 — Accessibility data-tables
Spec NFR-07 requires a data-table alternative for every chart; currently only SVG `aria-label`s exist. Highest-leverage compliance item, and it doubles as a power-user feature (sortable/copyable numbers).

### R7 — LLM phase gate stays as written
Do not start the LLM phase until the owner confirms Ollama is installed and reachable at `http://127.0.0.1:11434`. The deterministic Liner Notes and curated playlists are good enough that a poor 1.5B-parameter experience would be a regression.
